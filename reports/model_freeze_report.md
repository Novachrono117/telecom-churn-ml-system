### The feature-preparation boundary

the persisted pipeline is applied to the OUTPUT of prepare_features(). It expects a validated feature matrix in canonical column order and does not validate one itself.

That boundary was fixed in Phase 4 and is **not moved here**. The persisted
object is not a self-validating endpoint: it assumes its input already satisfies
the contract. Turning that into a public prediction interface — payload schema,
validation errors, response shape — is Phase 11's subject, and nothing of it is
anticipated in this phase.

### The full inference function, and why the `.joblib` does not cover it

```text
raw input
    ↓
churn.preprocessing.contracts.prepare_features(...)
    ↓
frozen sklearn pipeline (preprocessor -> classifier)
    ↓
predict_proba(...)
    ↓
positive-class probability (column resolved from classes_)
    ↓
probability >= 0.3272694566222328
```

**Only the middle of that chain is inside the serialised file.** Two links are
not, and both can change a prediction while every fingerprint of the model itself
stays identical:

- **`prepare_features` runs before the pipeline is reached.** prepare_features runs BEFORE the persisted pipeline and is therefore outside everything the model's own fingerprints can see. A change to it would alter the values handed to the model while pipeline_sha256, model_fingerprint_sha256, the feature names, the threshold and the hyperparameters all stayed identical. Its source is fingerprinted here so that cannot happen silently.
- **`TotalChargesCleaner` is inside the pipeline, but only by reference.** A
  pickle stores fitted *state* — arrays, hyperparameters — while classes are
  stored as a module path: the stream carries
  `churn.preprocessing.transformers`, and unpickling imports whatever that module
  currently defines. Editing its `transform` changes what the loaded pipeline
  computes, with `pipeline_sha256` and `model_fingerprint_sha256` both unmoved.

Section 8 closes both gaps by fingerprinting source.

## 4. Calibration policy

**`calibration_policy = NONE`** — `calibrated: False`.

NONE was the outcome of the Phase 9A gate, not an omission: neither sigmoid nor isotonic calibration cleared the pre-registered eligibility rule, so no calibration layer was adopted and the frozen logistic regression keeps emitting its own probabilities. See reports/calibration_report.md; the result is not reinterpreted here.

The probability the decision rule acts on is therefore
`pipeline.predict_proba(X)[:, positive_class_column]` of the uncalibrated logistic
regression. No calibrator is present in the persisted object, and an integrity
check asserts its absence rather than assuming it.


selected in Phase 9B by applying the pre-registered F1-maximisation policy to out-of-fold probabilities of the training pool, after a nested evaluation showed the procedure beating the 0.5 default in 5/5 outer folds. See reports/threshold_report.md; the result is not reinterpreted here.

value recorded here is the value that will be applied, at full double precision.

## 6. Decision rule

```text
predict churn if P(Churn = 1 | x) >= 0.3272694566222328
```

| Property | Value |
| --- | --- |
| Expression | `positive = probability >= final_threshold` |
| Comparison | `>=` |
| Probability | `pipeline.predict_proba(prepare_features(X))[:, positive_class_column]` |
| Fitted classes | `[0, 1]` |
| Positive class label | `1` (Churn = Yes) |
| Positive class column | `1` |
| Negative class label | `0` |

Two things are written down that are usually left implicit, because both are
places where a freeze can be silently wrong:

- **the boundary.** a customer whose probability equals the threshold exactly is predicted POSITIVE. The comparison is >=, not >. `>` and `>=` differ on exactly the
  customers whose probability equals the threshold; with a threshold read from a
  stored decimal that set is usually empty and occasionally is not, and "usually
  empty" is not a specification;
- **the column.** The positive-class column is resolved from `classes_`, never
  assumed to be column 1. The assumption happens to hold for this estimator and
  is still the wrong thing to record: reading the wrong column would invert every
  decision without raising anything.

**Two fingerprints, answering different questions.**

- **`model_fingerprint_sha256`** hashes the *learned parameters* — transformed
  feature names, coefficients, intercept, `n_iter_`, scaler mean/scale/variance,
  encoder categories — under a canonical JSON encoding in which every double
  round-trips exactly. This is the **identity of the model**: two objects with
  this value make the same predictions, whatever pickle protocol or library build
  produced them. It is the check that decides.
- **`pipeline_sha256`** hashes the file bytes. It catches a corrupted or swapped
  file, but it is a property of the *file*, not of the model, and it is not
  guaranteed to survive a change of environment.

**The binary is not committed, and that is deliberate.** `artifacts/` is
git-ignored by an existing repository convention for regenerable model files.
the file is regenerable by `uv run python scripts/freeze_model.py` from the frozen split, the frozen builder and the frozen training pool; both fingerprints must come out unchanged. That is a stronger guarantee than storing the binary would be:
it proves the frozen object is reproducible from source, rather than merely
present. The *contract* — this policy, with both fingerprints — is versioned, and
that is what makes the freeze provable.

`protocol` and `compress` are pinned rather than left at their defaults. A future
interpreter raising `pickle.DEFAULT_PROTOCOL` would otherwise change every byte
of the file, and its digest, without anything about the model having changed.

### Code provenance — freezing the inference function, not only the object

**Strategy:** whole-file SHA-256 of every source file that materially determines the frozen inference function, plus the configuration and the dependency pins. No source parsing, no AST normalisation, no comment stripping.

**Digest definition:** SHA-256 of the file's UTF-8 text with newlines normalised to \n. Not a raw byte hash: a byte hash changes when the checkout's line endings change, which would fail the freeze for a reason unrelated to the code. .gitattributes already pins this repository to LF, so the two agree today; normalising keeps the digest valid in a checkout that ignores it, such as a zip download or a Colab upload.

> **Caveat, stated plainly.** WHOLE-FILE hashing means an UNRELATED edit in one of these files — a docstring, a new helper, a reordered import — also invalidates the freeze. That is deliberate and fail-closed: the alternative, hashing only the functions believed to matter, would silently miss a changed constant, a changed helper or a changed default. A freeze that survives an edit it should have caught is worse than one that fails on an edit it need not have caught.

`prepare_features` additionally carries a **function-level** digest
(`94ca586de7235df5…`, from
`inspect.getsource`). It is a **diagnostic, not the gate**: when a freeze fails,
the pair localises the change — both moving means the function itself was
edited, only the module moving means something else in the same file was. It is
never used alone, because `prepare_features` delegates to
`validate_feature_matrix` and reads `FEATURE_COLUMNS`, neither of which appears
in its own source.

### `--verify` is strictly read-only

The verification mode reads, hashes and compares. It **does not** fit, dump,
write, overwrite or repair anything, and the separation is absolute:

| `FREEZE` (no flag) | `--verify` |
| --- | --- |
| fits on the training pool | never fits |
| writes the `.joblib` | never writes |
| writes the policy and this report | never writes |
| produces the freeze | judges an existing one |

Fail-closed in every direction, and none of these is repaired automatically:

| Condition | Result |
| --- | --- |
| pipeline file absent | **FAIL** — not rebuilt |
| pipeline bytes tampered | **FAIL** — not corrected |
| model fingerprint divergent | **FAIL** — not corrected |
| policy file absent | **FAIL** — not regenerated |
| any provenance digest divergent | **FAIL** — policy not refreshed |

A verification that regenerated whatever it found missing could never fail, and a
check that cannot fail is not a check. Three independent kinds of evidence hold
this property in the test suite: writes and fits are monkeypatched to raise while
`--verify` runs to completion; every artefact's SHA-256 and mtime is compared
before and after; and an AST audit of the `verify` function asserts it references
no write or fit operation.

## 10. Reload fidelity and determinism

The pipeline was written, read back, and both objects scored the same 256 training-pool rows. The probabilities are bit-identical (largest absolute difference 0.0e+00), the decisions at the frozen threshold are identical, and the model fingerprint of the reloaded object matches the one written to the policy. **No label was read and no metric was computed**: this demonstrates serialisation fidelity, not performance.

**What is and is not claimed about determinism:**

- **Prediction determinism — verified.** The reloaded pipeline reproduces the
  probabilities of the in-memory object exactly, and a refit on the same data
  reproduces the same learned parameters bit for bit.
- **Byte-level determinism — verified in this environment, not claimed beyond
  it.** Repeated dumps of the same fitted object, and dumps of independently
  refitted objects, produced identical bytes here. `joblib` serialisation depends
  on the pickle protocol, on the numpy build and on the module paths of the
  classes involved, so a different environment may legitimately produce different
  bytes for the same model. That is precisely why `model_fingerprint_sha256`
  exists and is the authoritative check: it is invariant to all of that.

## 12. Limitations

- **This is a freeze, not an evaluation.** No number in this report is
  performance, because none was computed.
- **The final fit has no held-out estimate of its own**, by construction: it uses
  every row. What is known about how this configuration generalises comes from
  the cross-validated results of Phases 5 to 9B, and the only unbiased estimate
  will come from Phase 9D.
- **Byte-level reproducibility of the `.joblib` is environment-scoped**, as
  section 10 states. The model fingerprint is not.
- **`joblib.load` raises a `DeprecationWarning` from inside `joblib` itself**:
  `numpy_pickle.py` assigns to `ndarray.shape`, which numpy
  2.5.1 deprecated. It comes from joblib
  1.5.3 — the latest published release — not from code in
  this repository, and there is no version to upgrade to yet. It is **not
  suppressed**, per the project's warning policy. It is harmless today: the
  round-trip is verified bit-identical in section 10, and a deprecation is not a
  behaviour change. It will need a joblib release before numpy removes the
  assignment.
- **The persisted object does not validate its input.** It expects the output of
  `prepare_features()`; the validating boundary is Phase 11's subject.
- **`handle_unknown="ignore"` means an unseen category encodes as all-zeros**
  rather than raising. That is the behaviour a deployed pipeline needs, and it is
  not a substitute for detecting unseen categories — monitoring is Phase 12.
- **`class_weight` stays `None` and
  stays closed.** It changes the objective the model is fitted on, so reopening
  it would reopen model selection.
- **Calibration stays `NONE`.** The threshold
  belongs to the raw probability and would have to be reselected if that changed.
- **The analyst-exposure limitation from Phase 3 still applies.**
- **Snapshot classification, not forecasting.** The dataset has no time
  dimension.
